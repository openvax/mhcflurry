# MHCflurry 2.5.10

## What changed

- **Cleaner prediction CSVs and consistent scan columns (#424):**
  - Added `--float-format` (e.g. `%.4f` or `%.6g`) to `mhcflurry predict` and
    `mhcflurry predict-scan`, and documented output column units (`affinity` in
    IC50 nM, `*_percentile` in 0–100%, `*_score` in 0–1) in `--help`.
  - Stopped `mhcflurry predict` from duplicating input `n_flank` / `c_flank`
    columns under `--prediction-column-prefix`.
  - Fixed `Class1PresentationPredictor.predict()` processing-only column order
    so `peptide, n_flank, c_flank` always matches the affinity/presentation
    order, and omitted the synthetic `sample_name="sample1"` column from
    `mhcflurry predict-scan` output when no `--alleles` are specified.
- **Quieter default CLI output (#425):**
  - Routed inference `Local workload plan` diagnostics to `logging.info` and
    unused unparseable pseudosequence-key load messages to `logging.debug`.
  - Removed raw `pandas.DataFrame` repr dumps from `mhcflurry predict-scan`
    FASTA loading and replaced truncated DataFrame reprs in
    `class1-reassign-mass-spec-training-data --verbose` with a compact preview
    of key columns including `measurement_value`.
  - Tightened the `predict-scan` default filter notice to a single clean line.
- **Clean one-line CLI errors instead of tracebacks (#426):**
  - Validated `--models` directory existence before affinity-only detection,
    single-character `--output-delimiter`, existing `--out` parent directories,
    `--peptide-lengths` syntax, missing CSV files/columns, and prediction/encoding
    errors across `predict`, `predict-scan`, and `pseudosequences` so routine
    user errors exit cleanly via `parser.error(...)`.
  - Clarified `FlankingEncoding` unsupported-length `EncodingError` wording.
- **Clean `--help` for training, selection, calibration, and `pseudosequences` (#427):**
  - Switched all eight train/select/calibrate CLI parsers from `usage=__doc__`
    to `description=__doc__` so argparse renders proper usage synopses, and
    moved `install_sigusr1_stack_trace_handler()` after `parse_args` so
    `--help` never emits `To show stack trace, run: kill -s USR1 ...`.
  - Documented missing option defaults, fixed help text typos, removed leaked
    reStructuredText double-backticks, and gave `mhcflurry pseudosequences` a
    concise plain-text description and option help.
- **Fixed `mhcflurry downloads` verbosity & subcommand help (#428):**
  - Made `--verbose` / `--quiet` mutually exclusive, ensured `--verbose` sets
    the root logger level to `DEBUG` even when handlers are already installed,
    suppressed the already-installed banner under `--quiet`, and added one-line
    help text to `fetch`, `info`, `path`, and `url` subcommands.

## Compatibility

- Existing `2.3.0` model weights and predictions are unchanged.
