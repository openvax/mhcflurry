# MHCflurry 2.5.4

Bugfix release addressing local parallelism, GPU/batch auto-sizing,
`torch.compile` thread coordination, cluster retry hygiene, custom allele key
resolution, and `mhcseqs >= 2.12.2` fragment-status handling. Existing `2.3.0`
model weights and standard predictions are unchanged.

## Highlights

- **Local parallelism, auto-sizing, and cluster execution fixes (`#580`–`#587`):**
  - `#580`: Honor `--backend` in serial mode (`num_jobs == 0`) instead of
    ignoring the requested PyTorch backend.
  - `#581`: Resolve `non_daemon_context()` dynamically per call rather than
    caching a stale process context across start-method changes.
  - `#582`: Use ceiling division in `auto_max_workers_per_gpu()` and validate
    worker-cap edge cases so GPU counts never under-allocate or divide by zero.
  - `#583`: Handle empty-string `TORCHINDUCTOR_COMPILE_THREADS`, honor
    `AUTO_VALUE`, and hoist thread-budget setup before warmup compilation.
  - `#584`: Cap GPU warmup `total_gb` against available host RAM so small-RAM
    hosts with large GPUs do not OOM during warmup.
  - `#585`: Guard `num_jobs=None`, reject negative `--gpus`, and make
    `chunk_ranges_for_local_parallelism(0)` return a clean serial range.
  - `#586`: Archive failed cluster attempt artifacts cleanly on retry and
    accept `argv=None` in `cluster_parallelism.worker_entry_point()`.
  - `#587`: Guard `choose_calibration_batch_shape()` against empty
    `model.networks` (`ZeroDivisionError`) and dual-pinned batch/chunk inputs.
- **Cross-species & custom allele robustness:**
  - `#597`: `AlleleKeyResolver.resolve()` now checks exact membership in
    `valid_keys` before invoking `mhcgnomes`, so custom allele keys registered
    via `add_allele_from_sequence(..., normalize_allele=False)` (such as
    engineered pocket mutants) work directly in `predict()`.
  - Align with `mhcseqs >= 2.12.2` (`pirl-unc/mhcseqs#140`): reject short
    both-halves exon fragments (`status="short"`) and other fragment statuses
    (`alpha1_only`, `alpha2_only`, `fragment_fallback`) by default unless
    `allow_fragments=True` / `include_fragments=True` is passed, and reject
    non-groove statuses (`too_short`, `invalid_boundaries`,
    `chain_inference_failed`). Verified with `mhcseqs 2.12.2` and
    `mhcgnomes 3.79.0`.
