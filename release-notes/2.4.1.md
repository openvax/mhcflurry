# MHCflurry 2.4.1

Completes the migration of `mhcflurry downloads` onto `datacache` for safe,
transactional, checksum-verified archive installation (#484). Model weights,
catalogue release (`2.3.0`), and predictions are unchanged.

## Highlights

- **`datacache` archive installation (`mhcflurry downloads fetch`):**
  - Replaces the legacy `urllib.request.urlretrieve`, manual split-part
    concatenation, custom `FileLock`, and manual `tarfile` extraction path with
    `datacache.install_archive(...)` and `datacache.inspect_archive(...)`.
  - Publishes extracted bundles and `DOWNLOAD_INFO.csv` receipts atomically into
    per-release `.datacache/<bundle>/` stores with bounded transport retries,
    resumable downloads for pinned single-archive bundles, and archive safety
    checks.
  - Preserves existing legacy `<release>/<bundle>/` installations read-only
    without modifying, moving, or overwriting them.
  - Routes `fetch` progress and status output to `stderr` so `stdout` remains
    clean.
  - Adds `--force` to `mhcflurry downloads fetch` for safe in-place
    refresh/repair (leaving the previous generation or legacy install intact on
    failure). Deprecates `--keep` (with a warning directing users to
    `--already-downloaded-dir`).
- **Pinned checksums and verification:**
  - Pins published SHA-256 checksums and byte sizes from `2.3.0`'s `SHA256SUMS`
    for `models_class1_presentation`, `models_class1_pan`, and
    `models_class1_processing` in `mhcflurry/downloads.yml`. Historical
    unpinned entries explicitly use `verified=False`.
  - Adds `mhcflurry downloads info [DOWNLOAD] --verify` for explicit full-tree
    integrity verification while keeping ordinary `list` and `info` lookups
    fast and offline.
  - Extends `downloads list --json` and `downloads info --json` with additive
    provenance fields (`layout`, `install_status`, `verified`,
    `trusted_checksum`, `fetched_at`, `archive_size`, `recorded_sha256`,
    `recorded_urls`).
- **Packaging & test compatibility:**
  - Removes the redundant direct `filelock` dependency from `pyproject.toml`
    (now managed transitively by `datacache`).
  - Updates `test/test_downloads_cli_harmonize.py` for compatibility with
    `datacache 1.35.0` (`platform_cache_dir`).
