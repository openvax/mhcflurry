# MHCflurry 2.5.11

Maintainability and dead-code cleanup across `class1_neural_network.py` and the
peptide encoding layer, with **zero changes to `2.3.0` weights or predictions**.

## Highlights

- **Split `class1_neural_network.py` (#506):**
  - Moved legacy Keras JSON config parsing, allele-representation width
    inference, Keras-layout NPZ weight conversion, and model/merged-model
    reconstruction into a dedicated public module
    [`mhcflurry/keras_model_config.py`](../mhcflurry/keras_model_config.py)
    (`is_keras_model_config`, `parse_keras_json_config`,
    `infer_allele_representation_dim_from_weights`,
    `placeholder_allele_representations`, `load_keras_weights_into_model`,
    `create_model_from_config`, `create_merged_model_from_config`).
  - Decomposed the 852-line `Class1NeuralNetwork.fit()` and 494-line
    `Class1NeuralNetwork.fit_streaming_batches()` into named, standalone-tested
    phase functions and state dataclasses in
    [`mhcflurry/class1_training.py`](../mhcflurry/class1_training.py)
    (`seed_training_rngs`, `compute_regularization_penalty`,
    `run_training_batch`, `run_prepared_training_batches`,
    `prepare_affinity_inputs`, `build_affinity_device_data`,
    `prepare_streaming_validation_tensors`, `evaluate_validation_epoch`,
    `update_early_stopping_and_checkpoint`, `iter_device_training_batches`,
    `run_affinity_training_epoch`, `run_streaming_training_epoch`,
    `record_fit_summary`).
  - Reduced `mhcflurry/class1_neural_network.py` from 4,569 lines to 2,911 lines.
- **Removed deprecated dense-vector encoding remnants (#419):**
  - Removed `FlankingEncoding.vector_encode` and `FlankingEncoding.encode` from
    `mhcflurry/flanking_encoding.py`.
  - Removed `EncodableSequences.variable_length_to_fixed_length_vector_encoding`
    from `mhcflurry/encodable_sequences.py`.
  - Removed the deprecated `peptide_input_is_indices=False` 3D dense-float
    forward branch from `Class1NeuralNetworkModel`; the model always embeds 2D
    index-encoded `(N, L)` peptide tensors via its frozen on-device table and
    raises a clear `ValueError` on non-2D inputs.
- **Consistent CSV parsing in pan-allele training (#513):**
  - Removed the undeclared optional `engine="pyarrow"` fallback in
    `mhcflurry/cli/train_pan_allele_models_command.py` so training CSV loading
    uses the standard pandas parser consistently regardless of whether
    `pyarrow` happens to be installed. (Legacy `.ix`/`.iteritems`, Python 2
    `print_function`/`six`, and `numpy>=2,<3` in `#513` were already resolved
    in `2.3.22`.)

## Empirical Verification

Verified bit-for-bit parity (`179 / 179` arrays identical, `max_abs_diff = 0.0`)
between unmodified `2.5.10` (`master`) and `2.5.11` across:
- Released model bundles (`2.3.0`, `2.2.0`, `2.0.0` `models_class1_presentation`,
  and historical `models_class1` Keras-format allele-specific weights)
- Legacy Keras Functional/Model JSON + Keras-layout weight loading (allele-specific
  and pan-allele DenseNet skip connections)
- Fixed-seed CPU `fit()` (pan-allele `pool_epochs=1` & `2` with LSUV,
  inequalities, sample weights, early stopping, `terminal`/`best` checkpoints;
  allele-specific skip-connections + BatchNorm + `validation_interval=2`),
  `fit_streaming_batches()`, and merged ensemble roundtrips.
