# MHCflurry 2.5.5

Bugfix release addressing training-loop, model-selection, ranking-metric,
model-comparison, and CLI edge cases (`#588`–`#595`). Existing `2.3.0` model
weights and standard predictions are unchanged.

## Highlights

- **Training & data-sampling fixes:**
  - `#588`: Fix shuffled `train_rounds` alignment and accept Python list inputs
    cleanly in `fit_allele_specific_predictors()`.
  - `#589`: Make `measurement_inequality` optional and provide a default
    `peptide_encoding` in `class1-train-pan-allele-models`.
  - `#590`: Handle zero-binder alleles cleanly in `RandomNegativePeptides`
    instead of crashing on empty positive sets.
- **Evaluation & model-selection fixes:**
  - `#591`: Handle `NaN` scores cleanly in `ppv_at_n()`.
  - `#592`: Fix `sample_id` handling, degenerate `_affinity_per_length` cases,
    and early input validation in `mhcflurry eval compare-models`.
  - `#593`: Scope `dropna(subset=...)`, handle `<2` equality-bound rows in
    `MSEModelSelector`, and fix cache keys in
    `class1-select-allele-specific-models`.
- **CLI fixes (`predict`, `predict-scan`, `downloads`):**
  - `#594`: Fix input validation, threshold filtering, delimiter/bz2 handling,
    and peptide-length range checks in `mhcflurry predict-scan`.
  - `#595`: Respect custom `--allele-column` / `--peptide-column` flags in
    `mhcflurry predict` and resolve `downloads fetch --release` dynamically
    from the catalogue.
