# MHCflurry 2.5.3

High-priority bugfix release addressing recent `2.5.x` regressions, NumPy 2 /
Pandas 3 compatibility crashes, and core affinity/processing/presentation edge
cases. Existing `2.3.0` model weights and standard predictions are unchanged.
Verified compatible with `mhcseqs >= 2.12.0` and `mhcgnomes >= 3.77.1`.

## Highlights

- **`2.5.x` regression and new-feature fixes:**
  - `#550`: Raise `csv.field_size_limit` temporarily when reading `manifest.csv`
    in `read_supported_alleles` / `read_supported_peptide_lengths`, fixing
    `_csv.Error` on pan-allele manifests whose `config_json` exceeds 128 KB.
  - `#551`: `mhcflurry downloads info --verify` now forwards `verify_files=True`
    into the prediction-models summary table, surfaces invalid/corrupt managed
    installs, and updates the integrity footer accurately.
  - `#552`: `mhcflurry.downloads.get_path()` no longer silently falls back to a
    stale legacy directory when a `.datacache`-managed store is damaged/invalid;
    `inspect_download()` reports the managed store path and
    `_resolve_default_override_path()` now checks managed stores before legacy
    directories.
  - `#553`, `#554`: Fix the fallback α1 Trp60 anchor index (`59`/`58`), remove
    the unsafe α2 fallback fast path that misaligned compensating-indel
    sequences, and guard `build_pseudosequences_from_mhcseqs` /
    `extend_allele_to_sequence_from_mhcseqs` against pandas `NaN` values.
  - `#555`: Clear `calibrate_percentile_ranks_fast` cache in `clear_cache()` and
    always synchronize `allele_embedding` on cache hit so prior `predict()` or
    `add_allele_from_sequence()` / `extend_alleles_from_mhcseqs()` calls cannot
    leave stale or NaN-padded embeddings.
- **NumPy 2.x and Pandas 3.x fixes:**
  - `#556`: Use `numpy.asarray(...)` instead of `numpy.array(..., copy=False)`
    for `sample_weights` and `output_indices` in `Class1NeuralNetwork.fit()`.
  - `#557`: Keep `None` entries as Python `None` in `AlleleEncoding` under
    Pandas 3 `StringDtype`.
  - `#558`, `#559`: Cast all-NaN checkpoint/provenance columns to `object` and
    integer `measurement_value` columns to `float` before assignment in
    `save_predictor`, `Class1ProcessingPredictor.save`, `training_provenance`,
    and `reassign_mass_spec_training_data`, and handle `pandas.NA` in
    `decode_sources`.
- **Core predictor correctness and edge-case fixes:**
  - `#560`, `#561`, `#562`, `#563`, `#570`: Reject merging optimized pan-allele
    predictors instead of silently dropping ensemble members, preserve
    `allele_to_canonical` in `merge()` and `models_dir` in `optimize()`,
    preserve `LocallyConnected1D` `activation` when serializing merged networks,
    skip merging multi-output (`num_outputs > 1`) models in `optimize()`, and
    key/invalidate/copy `Class1NeuralNetwork.prediction_cache` properly.
  - `#571`: Preserve restored/unpickled weights when calling
    `Class1ProcessingNeuralNetwork.fit()`.
  - `#573`, `#574`, `#576`: Use positional flank mapping in
    `Class1PresentationPredictor.predict()` (preventing swapped/`NaN` flanks on
    non-RangeIndex `Series`), fix `alleles=[]` processing-only mode,
    `alleles={"s1": []}`, `alleles={}`, and empty-peptide `sample_names`
    handling, normalize `None`/`NaN` flanks and positional indexing in
    `FlankingEncoding`, fix off-by-one `supported_peptide_lengths` in
    `EncodingError`, and preserve empty/`"NA"` flanks in
    `read_processing_training_data` and `train_presentation_models_command`.
