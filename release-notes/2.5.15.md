# MHCflurry 2.5.15

Dependency cleanup and Biopython removal release (`#501`, `#513`), with **zero
changes to runtime prediction code, `2.3.0` weights, or predictions**.

## Highlights

- **Removed Biopython (`#501`):**
  - Migrated all three remaining `Bio.SeqIO` scripts in `downloads-generation/`
    (`allele_sequences/filter_sequences.py`,
    `allele_sequences/make_allele_sequences.py`, and
    `data_references/process.py`) to `mhcflurry.fasta.FastaParser`, preserving
    identical header formatting, duplicate-allele longest-sequence handling,
    record ordering, and `.fasta.gz` support without adding heavy runtime
    dependencies.
  - Dropped `biopython` from `downloads-generation/data_references/requirements.txt`.
  - Kept the lightweight, zero-extra-dependency `mhcflurry/fasta.py` reader
    (benchmarking showed `biotite.sequence.io.fasta.FastaFile.read_iter` is a
    pure-Python loop with ~1.28s cold import overhead and 5 transitive
    dependencies for only 5–24 ms difference on a 20k-protein proteome).
- **Synced `requirements.txt` with `pyproject.toml`:** Added missing
  `datacache>=1.37.0,<2` and raised `mhcgnomes` floor to `>=3.87.2`, guarded by
  a new packaging regression test in `test/test_packaging.py`.
- **Regression tests:** Added `test/test_downloads_generation_fasta.py` covering
  the `filter_sequences.py` → `make_allele_sequences.py` round-trip and
  `data_references/process.py` `.fasta.gz` parsing, plus packaging guards in
  `test/test_packaging.py`.
