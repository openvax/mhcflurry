# MHCflurry 2.5.16

Reliability, streaming, and performance improvements with **zero changes to
`2.3.0` weights or predictions**.

## Highlights

- **Streaming `--chunk-size` for `mhcflurry-predict-scan` ([#175](https://github.com/openvax/mhcflurry/issues/175)):**
  - Added `--chunk-size N` to `mhcflurry predict-scan` / `mhcflurry-predict-scan`
    to stream FASTA, CSV, and `--sequences` inputs in bounded-memory batches of
    at most `N` sequences while reusing the loaded predictor (or worker pool)
    and streaming filtered CSV output.
  - Preserves exact column schema and bit-identical predictions relative to
    unchunked runs (including empty inputs and chunks with zero passing rows);
    when `--chunk-size` is set, predictions are sorted within each chunk rather
    than globally across the entire input.
- **~14x faster processing flank encoding ([#290](https://github.com/openvax/mhcflurry/issues/290)):**
  - Replaced the pandas `.str.pad`/`.str.slice`/`.str.upper` + `EncodableSequences`
    pipeline in `FlankingEncoding._fixed_length_index_encoding()` with a direct
    256-entry ASCII byte lookup table (with automatic fallback for non-ASCII
    inputs).
  - Benchmarked on `250,000` flanked peptides (`15` aa N/C flanks): `1.915 s` →
    `0.137 s` (**`14.0x` speedup**) with bit-identical `int8` arrays, peptide
    lengths, masks, and `Class1PresentationPredictor` outputs.
- **Explicit processing preparation sampler provenance ([#440](https://github.com/openvax/mhcflurry/issues/440)):**
  - `processing_matching.initialize_matching_artifacts()`,
    `processing_preparation.sample_preparation_steps()`, and
    `processing_preparation.prepare_sample()` now accept an explicit `sampler`
    name (defaulting to `"unknown"` when omitted rather than mislabeling
    arbitrary callbacks as `"numeric-positions-v1"`) and record
    `candidate_representation` separately (`"numeric-candidate-pool-v1"` /
    `"protein-indices-v1"` vs `"dataframe"`).
  - Updated `scripts/training/release_exact/make_train_data.processing.py` and
    `scripts/training/prepare_processing_evaluation.py` to pass explicit
    sampler identifiers.
- **Download catalogue completeness regression test ([#374](https://github.com/openvax/mhcflurry/issues/374)):**
  - Added `test_current_release_retains_unchanged_bundles_and_replaces_model_urls`
    in `test/test_model_catalogue.py` enforcing that the `current-release`
    stanza (`2.3.0`) retains every unchanged `2.2.0` catalogue entry while
    replacing the three model bundle URLs with checksummed `2.3.0` assets.
- **Worker-pool implementation docstring accuracy ([#411](https://github.com/openvax/mhcflurry/issues/411)):**
  - Updated the stale `SimpleQueue`/backup-queue note in
    `mhcflurry/parallelism/worker_pool.py` to match the current shared-memory
    `Array`/`Value` slot-assignment design and verified the `spawn` recycling
    test passes cleanly.

## Verification

- Verified `FlankingEncoding` bit-identical parity against the pre-`2.5.16`
  `EncodableSequences` reference across flank lengths (`0`–`15`), case,
  unsupported characters, non-ASCII fallback, and `throw=True/False`
  (`test/test_flanking_encoding.py`).
- Verified `mhcflurry-predict-scan --chunk-size` parity against unchunked runs
  on FASTA, CSV, `--sequences`, empty inputs, and 0-hit filtered chunks
  (`test/test_predict_scan_command.py`).
- Existing `2.3.0` model weights and predictions are completely unchanged.
