# MHCflurry 2.5.2

CLI discovery speedups, cleaner validation errors, and bounded download
timeouts/retries. Model weights, catalogue release (`2.3.0`), and predictions
are unchanged.

## Highlights

- **Fast torch-free CLI metadata discovery:**
  - `mhcflurry predict --list-supported-alleles`,
    `mhcflurry predict --list-supported-peptide-lengths`, and the matching
    `mhcflurry predict-scan` flags now read `manifest.csv` and pseudosequence
    metadata directly via `mhcflurry.affinity.persistence.read_supported_alleles`
    and `read_supported_peptide_lengths` without importing PyTorch or loading
    neural network weights.
  - `mhcflurry predict-scan --list-supported-alleles` and
    `--list-supported-peptide-lengths` no longer emit unrelated threshold
    filtering notices to `stderr`.
  - `mhcflurry.class1_encoding.peptide_sequences_to_network_input` avoids
    importing `mhcflurry.numeric_sequences` (and `torch`) for plain string
    peptide inputs.
- **No duplicate `WARNING` logs on raised validation errors (#443):**
  - `Class1AffinityPredictor.predict_to_dataframe` and
    `predict_cartesian_pan_allele` now log validation warnings only when
    `throw=False`, eliminating duplicated `WARNING` + exception output for
    downstream callers such as Topiary when `throw=True`.
- **Bounded download timeouts and retries (#462):**
  - `mhcflurry.downloads.install_download` now defaults to
    `timeout=60` seconds per connect/read attempt (`DEFAULT_DOWNLOAD_TIMEOUT`)
    and `max_retries=3` (`DEFAULT_DOWNLOAD_MAX_RETRIES`) when forwarding
    transport options to `datacache.install_archive`.
